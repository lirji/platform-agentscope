# 节点持久恢复实施报告

## 交付范围

S1 中央检查点、S2 Python 恢复执行已经实现。S3 隔离 MySQL 与两个独立 worker 的 SIGKILL 接管通过，S4 Git 交付进行中。此前 S6 的“仅设计”状态被本轮实现取代；生产启用仍为未执行。

## 设计与实现

技术选择、需求边界和影响分析见 [PLAN](PLAN.md)。复用 Java MySQL/MyBatis 事务、任务租约和分发，不新增依赖/中间件，也不在 Python 建第二任务权威。

- 新增 V5 检查点表与 POST `/async/tasks/{id}/checkpoint`。专用 worker JWT `checkpoint` action 绑定任务/tenant/actor/worker；租约 epoch 放在请求中与数据库权威值核对。读取同样需要活动租约。
- 父任务行锁保护身份、未过期租约、非终态、CAS revision 与事件写入；事件失败整体回滚。取消/接管与检查点使用同一行锁。清理沿用父任务逻辑删除，不宣称物理擦除。
- checkpointVersion=1 的 worker 才能领取 `agent.readonly.{dag,dag-plan,analyst,process}.v2`，旧 worker 默认版本0只能领 v1。新 worker 仍能处理 v1；单 Agent run 继续 v1。
- Python 保存经过安全校验/回退的计划、各次 DAG 的节点、汇总、评审和重规划。输入、身份/部门/scope、运行配置、模型/提示/工具版本通过摘要关联。依赖结果版本变化会使下游失效。
- 仅成功、没有工具步骤且上游均可复用的节点可跨进程复用，期限是本任务固定 deadline。工具调用节点重新执行，重新经过现有权限校验和读取路径；其下游重新计算。纯计算不适用轮内30秒缓存规则。
- 模型调用前原子保存累计预留。失败/未知usage不退还，接管不重置次数、token或deadline。保存未知/租约冲突停止续租，交由后续领取恢复；错误契约、版本不匹配和已耗尽预算失败关闭。
- 只读工作集和新协议默认关闭；拒绝 inline/旧调度模式启用恢复。外部/MCP/浏览器/代码执行/写工具仍按 durable 角色禁止。

## 证据

- Python：584 项测试通过（最终枚举化后的复验另见 TEST_RESULT）；包含节点复用、工具链失效、规划/回退/重规划恢复、预算跨进程范围、未知提交失败关闭和并发快照。
- Java：模块与上游 196 项通过，真实隔离 MySQL 的调度及检查点 suite 通过；覆盖旧worker隔离、CAS竞争、跨租户/actor、旧epoch、过期、取消、事务回滚、逻辑删除与大小限制。
- 真实中央 Java + MySQL + Python API/worker：首节点已提交、第二节点调用中 SIGKILL，第二进程接管，首节点不重跑。实际 provider 调用4次，持久预算4次，任务成功，旧写入被拒；本次从kill到验收16.00秒（含15秒测试租约），仅是本地样本，不承诺生产RTO。
- 模型为本地假OpenAI端点，无真实付费模型或业务数据。仅创建并清理脚本自己的随机测试库；共享库、原Java知识ETL工作树、历史工作树均未清理。

## 兼容、风险与回滚

API/worker 需同一运行配置与版本；先迁移中央V5并升级分发服务，再启动新worker，最后开启API入队开关。应在升级前排空旧worker的分发服务副本；旧中央服务不了解新kind不能与新中央服务共同领取v2。

检查点不是备份，也不是 exactly-once 外部效果。RUNNING 节点的未提交输出可能丢失并重做、重复模型费用；最多3次领取及固定任务预算继续约束。快照上限2MiB/256操作，默认DAG规模有界；容量/生产延迟未实测。任务和检查点按原24小时保留策略逻辑隐藏，备份/物理擦除按既有运维治理。

回滚先停止v2提交，排空或取消v2，再回退worker；保留迁移表。旧worker无法处理v2，不能仅回滚镜像后声称旧任务继续恢复。不涉及生产部署、流量切换、写节点补偿和灾备RPO承诺。
